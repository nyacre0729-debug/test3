# Архитектура и материалы курсового проекта
## «Анализ востребованности IT-навыков на рынке вакансий Москвы (данные trudvsem.ru)»

---

## 1. Цели и задачи анализа
1. **Расчёт** — какие технологии наиболее популярны в IT-вакансиях Москвы (частотность упоминаний в описаниях).
2. **Выявление зависимости** — как зарплата зависит от требуемого опыта работы.
3. **Классификация** — группировка вакансий по требуемому опыту.
4. **Географический анализ** — распределение вакансий по округам Москвы.
5. **Визуализация** — графическое представление всех результатов.
6. **Прогноз** — линейная регрессия зарплаты по опыту, числу навыков, уровню должности и образованию (файл `predict.py`, R²=0.17 на log-шкале).

---

## 2. Источник данных и его оценка
**Источник:** единая платформа «Работа в России» (trudvsem.ru), раздел открытых данных.

| Характеристика | Значение |
|---|---|
| JSON API | `https://opendata.trudvsem.ru/api/v1/vacancies/region/77` |
| Пакетная выгрузка (используется) | `https://opendata.trudvsem.ru/csv/vacancy.csv` |
| Объём выгрузки | ~1,9 ГБ, **480 576 вакансий** по всем регионам РФ |
| Москва (ОКТМО 7700000000000) | **15 876** вакансий |
| IT-вакансии Москвы | **903** (офиц. отрасль + ключевые слова в названии) |
| Периодичность обновления | ежедневно |

**Модель данных источника:** реляционная, 80 полей на запись (id, stateRegionCode, vacancyName, professionalSphereName, salaryMin/Max, experienceRequirements, hardSkills, responsibilities и др.). Подробная ER-диаграмма — файл `figures/ER_diagram.png`.

**Выявленные ограничения источника:**
1. **Сломанная пагинация JSON API.** Параметры `page`/`offset` игнорируются сервером; при `offset > 100` возвращается HTTP 500. Доступно не более ~100–200 записей. Из-за этого первичный сбор дал 500 строк с 9 уникальными вакансиями (зацикливание одной страницы).
2. **Москва < требуемых 50 тыс.** В открытых данных Москвы всего ~15,9 тыс. вакансий, поэтому требование «≥50 тыс. записей» закрыто общероссийской выгрузкой (480 тыс.).
3. **`hardSkills` заполнен в <0,6%** записей — навыки извлекаются регулярными выражениями из названия + обязанностей.
4. **Разделитель CSV — «|» без экранирования**, в ~1% строк «|» встречается внутри текста (такие строки пропускаются при парсинге).
5. **Нет поля административного округа** — распределение аппроксимировано по названию улицы в адресе (~55% адресов не распознано).

## 3. Архитектура и стек
```
trudvsem.ru (открытые данные)
   │  пакетная выгрузка vacancy.csv (1,9 ГБ, ежедневно)
   ▼
get_data.py ── скачивание → фильтр region=77 ──► PostgreSQL  (таблица vacancy)
   │
   ▼
vacancy_moscow.csv (15 876)   /   vacancy.csv (этап 2, данные партнёра)
   │
   ▼
analyze.py ── 5 задач ──► figures/*.png , results/*.csv
```

**Стек:** Python 3, pandas, matplotlib, requests, psycopg2; PostgreSQL; Git; Docker (дистрибутив).

| Компонент | Файл | Назначение |
|---|---|---|
| Сбор данных | `get_data.py` | скачивание выгрузки → фильтр Москвы → запись в БД |
| Схема БД | `make_table.sql` | создание таблицы `vacancy` |
| Анализ | `analyze.py` | 5 задач + графики + таблицы |
| ER/UML | `figures/ER_diagram.png` | модель данных |
| Дистрибутив | `Dockerfile`, `docker-compose.yml`, `run.sh` | установка «одной командой» |

## 4. Масштабируемость решения
1. **По данным:** выгрузка уже содержит все регионы РФ — переход на другой регион = смена ОКТМО; исторические срезы = ежедневные дампы выгрузки.
2. **По коду:** потоковая обработка `pandas` чанками (`chunksize`), фильтрация на лету без загрузки 1,9 ГБ в память целиком.
3. **По инфраструктуре:** Docker-образ + Compose; далее — вынос на облако (Яндекс Cloud), партиционирование по `region`, замена pandas на Spark для полного датасета.

## 5. Похожие проекты и новизна
**Похожие работы (реальные):**
- Аналитика вакансий через **HH.ru API** — тема, рекомендованная самим преподавателем; после лета 2026 HH API доступен только по токену.
- Датасеты вакансий **HeadHunter на Kaggle** («HeadHunter job postings») и проекты по зарплатам/навыкам на их основе.

**Что нового в нашем решении:**
1. Использован **государственный портал trudvsem.ru** (без токена, в отличие от HH).
2. Обнаружена и обойдена **сломанная пагинация API** — переход на официальную пакетную выгрузку дал полный срез (480 тыс.), которого нет в аналогичных учебных проектах.
3. Полный срез по России + отдельный срез Москвы + выделенный IT-сегмент.
4. Оценка ограничений источника (объём, блокировки/лимиты API) — требование из критериев оценки.

## 6. Запуск (для обычного пользователя)
```bash
docker compose up          # поднимает PostgreSQL + выполняет анализ
# результат: figures/*.png , results/*.csv
```
Полный цикл со скачиванием выгрузки (тяжёлый, ~1,9 ГБ):
```bash
bash run.sh                # db + get_data.py + analyze.py
```
